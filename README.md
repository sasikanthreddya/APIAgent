# API Automation Agent (Java) - Toolshop

Java/Cucumber/TestNG API automation for the self-hosted
[toolshop-clone-api](../ToolshopCloneApi) (`localhost:8070`). Every resource
goes through a review gate before any code exists: drafted from the live API,
reviewed by a human, then generated. Jenkins runs the resulting suite as
plain compiled TestNG/Cucumber - **no agent and no LLM at test time**.

Cucumber 7 + TestNG + REST Assured + AssertJ. Reporting: Cucumber HTML/JUnit
XML in `target/`, plus Allure.

## How it's built

Two skills run the gate - see `CLAUDE.md` for the full rules.

| Skill | Does | Produces |
|---|---|---|
| `/flow-doc-gen <resource>` | Grounds a resource against the live Swagger + curl | One file: `flows/<resource>.md` (steps + every scenario's request/expected-response JSON, inline) |
| *(you review it, correct anything wrong, say "generate")* | | |
| `/code-gen <resource>` | Builds what the approved flow doc describes | `.feature`, step definitions, client, cleanup wiring - then runs the suite green |

One resource (or Swagger-tag-sized slice) per pass. Nothing is pre-built
ahead of its own review.

## Running it

```bash
mvn clean test                                 # full suite, against the clone
mvn test -Dcucumber.filter.tags="@smoke"       # smoke subset only
mvn test -Dcucumber.filter.tags="@auth"        # one resource only
mvn test -Dapi.baseUrl=http://localhost:8091   # against a different environment
mvn allure:serve                               # Allure report from target/allure-results
```

## Configuration

`src/test/resources/config.properties` holds the defaults (base URL, seeded
customer/admin credentials). Any key can be overridden on the command line:

```bash
mvn test -Dapi.baseUrl=http://localhost:8091 -Dadmin.email=admin@example.test
```

Resolution order: `-D` system property, then `config.properties`, then a
fast failure - no silent third default.

## Layout

```
flows/*.md                        review gate + source of truth, per resource (request/response JSON inline)
src/test/resources/features/      Gherkin, generated 1:1 from an approved flow (pinned via # flow-sha header)
src/test/resources/config.properties   base URL + seeded creds
src/test/java/.../steps/          step definitions, generated per resource (assertions live here only)
src/test/java/.../context/        TestContext (scenario state + cleanup registry), ResourceType
src/main/java/.../client/         Http, ApiResponse, BaseClient, Role, one class per generated resource
src/main/java/.../config/         ConfigManager
scripts/check-flow-drift.mjs      fails the build if a flow changed but its .feature didn't
.claude/skills/                   flow-doc-gen and code-gen
```

`sprint-input/` is retired - an older per-scenario-file convention, kept
only for historical reference. Don't add anything new there.

## Flow-drift check

`.feature` files are hand-written from `flows/*.md`, not generated by a
tool, so nothing enforces they stay in sync except this check. Each
`.feature` pins a sha256 of the flow it was written from in its first line.

```bash
node scripts/check-flow-drift.mjs          # verify flows match features
node scripts/check-flow-drift.mjs --write  # re-pin after an intentional change
```

## Jenkins

`Jenkinsfile` is a Windows-agent pipeline (`bat` steps) with `API_BASE_URL`
and `SUITE` parameters, publishing Surefire's JUnit XML and archiving the
Cucumber HTML report and Allure results.
